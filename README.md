# ECLIPSE RP

GTA V RolePlay-сервер на RAGE Multiplayer.

Монорепозиторий: общий контракт событий, серверная логика, клиент и интерфейс
собираются из одного дерева и не могут разойтись в именах событий или правилах
валидации.

---

## Требования

- Node.js 20+
- PostgreSQL 14+
- RAGE Multiplayer server files

## Быстрый старт

```bash
npm install

cp .env.example .env        # заполнить доступы к БД
npm run migrate             # применить миграции

npm run build               # собрать всё в dist/
```

Скопировать содержимое `dist/` в папку сервера RAGE MP:

```
dist/packages/eclipse/          → <server-files>/packages/eclipse/
dist/client_packages/index.js   → <server-files>/client_packages/index.js
dist/client_packages/eclipse/   → <server-files>/client_packages/eclipse/
```

Переменные окружения сервер читает из процесса — задайте их в окружении, из
которого запускается RAGE MP. Без обязательных переменных сервер не стартует:
тихий запуск с дефолтным паролем базы опаснее, чем падение.

## Разработка

```bash
npm run dev:cef      # интерфейс в браузере, без запуска игры
npm run typecheck    # tsc -b по трём пакетам
npm run verify       # typecheck + build + сквозной тест
```

`npm run dev:cef` открывает интерфейс в обычном браузере: мост к клиенту
переключается в режим заглушки, экраны можно верстать без GTA.

## Проверка

```bash
npm run test:smoke   # бандл грузится, обработчики зарегистрированы
npm run test:e2e     # сквозной флоу против настоящей базы
```

Сквозной тест подменяет глобальный `mp` и прогоняет путь
«подключение → регистрация → вход → создание персонажа → выбор персонажа»,
включая негативные сценарии: неверный пароль, перебор, занятое имя, занятый
слот, попытка войти за чужого персонажа.

Требует доступную базу:

```bash
DB_NAME=eclipse_rp DB_USER=eclipse DB_PASSWORD=... npm run test:e2e
```

## Структура

```
packages/shared    контракт: события, типы, коды ошибок, правила полей
packages/server    авторитетная логика
packages/client    посредник между интерфейсом и сервером
packages/cef       интерфейс (Vue 3)
database/          SQL-миграции — источник правды о схеме
tools/             проверки, которые нельзя выразить компилятором
docs/              карта проекта, роадмап, журнал отладки
```

## Состояние

Готовы фундамент и вход в игру: конфигурация, логирование, сессии, RPC с
лимитами, база и миграции, регистрация, вход, выбор и создание персонажа, спавн,
дизайн-система и три экрана интерфейса.

Что отсутствует — перечислено явно в конце `ECLIPSE_PROJECT_MAP.md` и не
имитируется заглушками. Ближайшая задача — сохранение состояния персонажа между
сессиями.

## Правила разработки

- Клиенту не доверяем: валидация на клиенте существует только ради UX,
  авторитетная — на сервере.
- Наружу уходит `ErrorCode`, stack trace остаётся в логе.
- Деньги внутри сервера — строки, не float.
- Схему меняем только миграциями; файлы миграций неизменяемы.
- Дублирующая система не создаётся: если реализация существует — расширяем её.
- Задача не закончена, пока не проверена. Записанный в файл код — не результат.
