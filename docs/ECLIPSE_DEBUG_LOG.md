# ECLIPSE_DEBUG_LOG

Журнал нетривиальных проблем. Правило: если исправление не помогло —
**не повторять то же самое**, а записать сюда, что проверено и с каким
результатом.

Формат: симптом → первопричина → исправление → чем проверено.

---

## #001 · CRITICAL · При недоступной базе сервер оставался без обработчиков

**Дата:** 2026-08-20 · **Статус:** исправлено

**Симптом.** Дымовой тест показал: при отсутствии PostgreSQL зарегистрировано
0 событий. Ни `playerJoin`, ни `playerQuit`, ни одного RPC.

**Почему это опасно.** Компилятор такое не ловит, а в игре это выглядит так:
сервер стартовал, порт открыт, игрок заходит — и молча оказывается в мире.
Без сессии, без авторизации, без единого обработчика. Открытый сервер без
правил хуже, чем сервер, который не пускает.

**Первопричина.** В `bootstrap()` порядок был:
`connectDatabase()` → модули → `registerLifecycle()`.
Исключение из `connectDatabase()` прерывало функцию до регистрации
жизненного цикла. Обработчик `bootstrap().catch()` аккуратно писал ошибку в лог
и на этом всё заканчивалось — сервер продолжал работать «пустым».

**Исправление.** `registerLifecycle()` вызывается **первым**, до базы и модулей.
Флаг `bootFailed` отличает «ещё запускается» от «запуск провалился», чтобы игрок
понимал, ждать ему полминуты или заходить позже.

**Проверено.** `npm run test:smoke` без базы: регистрируются 3 события
жизненного цикла, игрок получает kick с текстом о технических работах.

**Урок.** Обработчики жизненного цикла — часть контракта «сервер отвечает за
игрока». Они не должны зависеть от успеха инициализации подсистем.

## #002 · HIGH · Сборка попадала в несуществующие папки RAGE MP

**Дата:** 2026-08-20 · **Статус:** исправлено

**Симптом.** Не проявлялся бы до первого реального запуска: сервер просто не
увидел бы ни серверный, ни клиентский код.

**Первопричина.** Два независимых расхождения со структурой RAGE MP:

1. Серверный бандл собирался в `dist/server_packages/eclipse/`. Такой папки в
   RAGE MP нет — серверные пакеты лежат в `packages/`.
2. Клиентский бандл собирался в `dist/client_packages/eclipse/index.js`.
   RAGE MP загружает **ровно один** клиентский entry point —
   `client_packages/index.js`. Файл в подпапке молча не выполняется.

**Дополнительно.** Скрипт сборки клиента удалял всю папку
`dist/client_packages/eclipse` — то есть стирал собранный CEF, если запускался
после него. Проявлялось бы только при определённом порядке сборки.

**Исправление.** Сервер → `dist/packages/eclipse/index.js`;
клиент → `dist/client_packages/index.js` с удалением только своих файлов;
CEF остаётся в `dist/client_packages/eclipse/cef/` и адресуется как
`package://eclipse/cef/index.html`.

**Проверено.** `npm run build`, раскладка `dist/` сверена со структурой
серверной папки RAGE MP.

## #003 · MEDIUM · Kysely не разворачивал типы временных меток

**Дата:** 2026-08-20 · **Статус:** исправлено

**Симптом.** Три ошибки `TS2352`/`TS2322`: `created_at` имел тип `Timestamp`
вместо `Date`, а `new Date()` не присваивался в `updateTable().set()`.

**Первопричина.** В схеме было `Generated<Timestamp>`, где `Timestamp` — уже
`ColumnType<...>`. Вложение `ColumnType` в `ColumnType` ломает разворачивание
типа при `SELECT`.

**Исправление.** Значение по умолчанию выражается через `| undefined` в
insert-типе самого `ColumnType`, поэтому обёртка `Generated` не нужна.
Добавлен `TimestampNullable` для колонок, допускающих `NULL`.

**Проверено.** `npm run typecheck` — 0 ошибок.

**Урок записан прямо в `infra/schema.ts`**, чтобы следующий разработчик не
повторил.

## #005 · MEDIUM · Дублирование обработчика моста CEF

**Дата:** 2026-08-20 · **Статус:** исправлено (предотвращено)

**Первопричина.** Белый список разрешённых событий и регистрация
`mp.events.add(CefEvent.Rpc, ...)` жили внутри модуля авторизации. При
добавлении модуля персонажей естественным движением было бы скопировать тот же
блок — и каждый модуль повесил бы собственный слушатель одного события.
Один запрос из интерфейса уходил бы на сервер столько раз, сколько модулей
зарегистрировано, с общим `requestId`.

**Исправление.** `client/core/cefBridge.ts`: обработчик ставится ровно один раз,
модули только дополняют белый список через `allowFromCef()`.

**Проверено.** e2e-тест: на каждый RPC приходит ровно один ответ.

## #006 · Заметка · Тест на гонку проверен «от противного»

**Дата:** 2026-08-20 · **Статус:** закрыто

Проверка «переподключение быстрее сохранения» легко могла оказаться
бесполезной: если операции и без блокировки успевают в нужном порядке, тест
проходит всегда и ничего не гарантирует.

Поэтому блокировка была временно убрана из `character.service.select`, и тест
прогнан заново. Обе проверки — позиции и здоровья — упали. Блокировка
возвращена, прогон снова зелёный.

**Урок.** Тест на состояние гонки без проверки от противного — это тест на
удачу планировщика. Так же стоит поступать с любой будущей проверкой
конкурентного доступа: сломать защиту, убедиться, что тест краснеет.

## Открытые вопросы

**Проверка бандла на настоящем рантайме RAGE MP.** Сборка проверена
компилятором и заглушкой `mp`, но реальный рантайм отличается: он не
поддерживает модули, использует устаревший движок и капризен к нативным
зависимостям. Первый запуск на живом сервере может выявить проблемы, которые
здесь принципиально не воспроизводятся — нужна лицензионная GTA V.

**Потеря позиции при жёстком падении процесса.** Автосохранение ограничивает
потерю тремя минутами, но не устраняет её. Обработчик `playerQuit` при краше не
выполняется. Уменьшать интервал ради этого не стоит — правильнее вынести часть
состояния в Redis, когда он появится (roadmap PHASE 1).

**Формат `player.ip` за прокси.** В `auth_log` пишется `player.ip`. Если сервер
окажется за прокси или балансировщиком, это будет адрес прокси, а не игрока, и
расследования по IP потеряют смысл. Проверить при развёртывании.
