# ECLIPSE_PROJECT_MAP

Карта проекта: что где лежит, как связано и почему сделано именно так.
Документ обновляется вместе с кодом — расхождение считается багом.

---

## 1. Стек

| Слой | Технология | Почему |
|---|---|---|
| Общий код | TypeScript 5.7 | Один контракт на server / client / CEF |
| Server | Node (рантайм RAGE MP) | Штатная платформа RAGE MP |
| Client | TypeScript → esbuild (IIFE, es2018) | Клиентский рантайм не понимает модули |
| CEF | Vue 3 + Vite | Реактивность без тяжёлого рантайма |
| БД | PostgreSQL 16 + Kysely + pg | Транзакции, `NUMERIC`, `JSONB`, частичные индексы |
| Пароли | `scrypt` из `node:crypto` | Memory-hard KDF **без нативных модулей** |
| Сборка | esbuild + Vite | Секунды, а не минуты |

### Решения, которые дороже всего менять потом

**PostgreSQL, а не MySQL.** Нужны предсказуемые транзакции для экономики,
`NUMERIC` для денег, `JSONB` для внешности персонажа и частичные UNIQUE-индексы
(`WHERE deleted_at IS NULL`) — на них держится корректность слотов и имён.

**Kysely, а не полноценная ORM.** Запросы остаются близкими к SQL и при этом
полностью типизированы. Нет кодогенерации и нативных бинарников, которые плохо
переживают рантайм RAGE MP.

**scrypt, а не bcrypt/argon2.** Оба — нативные модули; обновление RAGE MP
регулярно ломает сборку биндингов. scrypt рекомендован OWASP и доступен из
стандартной библиотеки. Параметры лежат внутри строки хэша, поэтому стоимость
можно поднять без миграции базы (`needsRehash`).

**Деньги — строки внутри сервера.** `NUMERIC` читается из PostgreSQL как строка
(см. `infra/db.ts`). Приведение к числу происходит ровно в одном месте — на
границе отправки в интерфейс. Float в финансах даёт расхождения на копейки,
которые потом невозможно объяснить игрокам.

**Один CEF-браузер на весь клиент.** Экраны — это состояния Vue, а не отдельные
браузеры. Каждый лишний браузер стоит памяти и кадров; именно множащиеся
браузеры чаще всего превращают RP-сборку в слайд-шоу.

## 2. Структура

```
eclipse-rp/
├── packages/
│   ├── shared/     контракт: имена событий, типы, коды ошибок, правила полей
│   ├── server/     авторитетная логика
│   ├── client/     посредник между CEF и сервером
│   └── cef/        интерфейс (Vue 3)
├── database/migrations/   SQL-миграции — источник правды о схеме
├── scripts/migrate.mjs    раннер миграций
├── tools/                 проверки, которые нельзя выразить компилятором
└── docs/
```

### packages/shared
Единственное место, где объявлены имена событий. Server, client и CEF импортируют
один и тот же модуль, поэтому опечатка в имени события — ошибка компиляции, а не
молчаливое «ничего не произошло».

- `events.ts` — `RpcEvent`, `ServerEvent`, `CefEvent`, `RpcTransport`
- `result.ts` — `Result<T>` и `ErrorCode`; наружу уходит только код, не текст
- `enums.ts` — `SessionState`, `AdminLevel`, `Gender`, `CHARACTER_SLOTS`
- `types/` — контракты аккаунта и персонажа + правила валидации полей

### packages/server
```
core/    config · logger · session · rpc · rateLimit
infra/   db · schema · cache
config/  world (точка спавна, модели, стартовый капитал)
modules/ account/ · character/
```
Каждый модуль разложен одинаково: `repository` (только SQL) → `service`
(правила, не знает о RAGE MP) → `controller` (RPC + лимиты + сущности игры).
Такое разделение позволяет тестировать сервис без игрового сервера.

### packages/client
```
core/    browser (CEF) · rpc · cefBridge · world
modules/ auth · character · session
```
Клиент не принимает решений. Он передаёт запросы и применяет состояние,
пришедшее с сервера.

### packages/cef
```
core/       bridge · rpc · notify · errors
components/ EButton · EField · EToastHost · EBrand
views/      AuthView · CharacterSelectView · CharacterCreateView
styles/     tokens.css (дизайн-система) · base.css
```

## 3. Потоки

### RPC: интерфейс → сервер
```
CEF          rpc(event, payload)
             └ mp.trigger('eclipse:cef:rpc', requestId, event, json)
Client       cefBridge: событие в белом списке?
             └ callServer → mp.events.callRemote(event, requestId, json)
Server       core/rpc: сессия есть? payload разбирается?
             └ controller → rate limit → service → repository → PostgreSQL
             └ player.call('eclipse:rpc:reply', [requestId, json])
Client       резолвит промис по requestId (или таймаут 15 с)
             └ cef.reply → window.__eclipse.receive
CEF          резолвит свой промис
```

Оба уровня RPC имеют таймаут. Зависший запрос обязан завершиться ошибкой —
иначе кнопка остаётся в состоянии вечной загрузки.

### Состояние сессии
```
Connecting → Authenticating → CharacterSelect → Spawning → Playing
```
Источник правды — сервер (`core/session.ts`). Клиент никогда не переводит себя
в мир самостоятельно: иначе одного подделанного локального события хватило бы,
чтобы войти без выбранного персонажа.

Сессии хранятся по `player.id` **с проверкой `socialClub`**: RAGE MP
переиспользует слоты игроков после дисконнекта, и без этой проверки новый игрок
унаследовал бы сессию предыдущего.

## 4. Безопасность

| Механизм | Где |
|---|---|
| Белый список событий, доступных из CEF | `client/core/cefBridge.ts` |
| Rate limit на каждый RPC | `server/core/rateLimit.ts` |
| Валидация на сервере (клиентская — только UX) | `*.validation.ts` |
| Наружу уходит `ErrorCode`, stack trace — в лог | `server/core/rpc.ts` |
| Проверка владения в самом SQL-запросе | `character.repository.findOwned` |
| UNIQUE-индексы как защита от гонок | `database/migrations/0001_init.sql` |
| Журнал попыток входа (успех и провал) | таблица `auth_log` |

Несуществующий аккаунт и неверный пароль возвращают **один и тот же** код, и для
отсутствующего аккаунта выполняется фиктивная проверка хэша — иначе форма входа
превращается в инструмент перечисления логинов.

## 5. Сборка и раскладка

`npm run build` собирает `dist/`, повторяющий структуру серверной папки RAGE MP:

```
dist/
├── packages/eclipse/index.js          → <server-files>/packages/eclipse/
└── client_packages/
    ├── index.js                       → <server-files>/client_packages/
    └── eclipse/cef/                   → адресуется как package://eclipse/cef/index.html
```

RAGE MP загружает **ровно один** клиентский entry point — `client_packages/index.js`.
Бандл в подпапке молча не выполнится.

Серверный код бандлится в один CJS-файл: рантайм RAGE MP резолвит `node_modules`
не так, как обычный Node.

## 6. Проверка

```bash
npm run typecheck   # tsc -b по трём пакетам
npm run build       # все пакеты
npm run test:smoke  # бандл грузится, обработчики зарегистрированы
npm run test:e2e    # сквозной флоу против настоящей базы
npm run verify      # всё вместе
```

`tools/e2e-flow.mjs` подменяет глобальный `mp` заглушкой и прогоняет путь
«подключение → регистрация → вход → создание персонажа → выбор персонажа».
Компилятор не поймает ни отсутствующий обработчик, ни ошибку в SQL, ни неверный
порядок состояний, а поднять RAGE MP в CI невозможно — нужна лицензионная GTA V.

## 7. Что реализовано, а что нет

**Работает и проверено:** конфигурация, логирование, сессии, RPC с лимитами,
подключение к БД, миграции, регистрация, вход, список/создание/выбор персонажа,
спавн, дизайн-система, три экрана интерфейса, уведомления.

**Явно отсутствует** (не имитируется заглушками):
- редактор внешности и сцена презентации персонажа;
- драйвер Redis — `REDIS_ENABLED=true` пишет предупреждение и использует память;
- организации: поле `organization` в карточке персонажа всегда `null`;
- сохранение состояния персонажа при выходе;
- HUD, инвентарь, транспорт, экономика.
